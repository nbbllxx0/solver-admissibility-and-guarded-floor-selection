# Analysis tables

Research-data deposit for the article *When a positive SIMP density floor is not
enough: solver admissibility and guarded floor selection in matrix-free 3D
topology optimization*.

These 50 CSV files are the per-state and per-run analysis tables from which every
figure and every table in the article is computed, including the unguarded
fixed-floor trajectories, the guarded held-out audits with their rejected-attempt
histories, the bridge fine-ladder study, the million-element scale check, and the
source metadata for the nine optimized-density inputs. They are the reduced
outputs of the experiment drivers in this repository, not raw solver logs: one
row per state, per trajectory step, per solve attempt, or per configuration.

## Scope

Included: the tables that the article's figures and tables are derived from.

Not included here: the nine stored optimized-density input fields used by the
transfer study, the SI gallery, and the million-element scale check. Those are
deposited in the sibling directory `../optimized_density_inputs/`, with their
own checksummed manifest; their source-run diagnostics are also tabulated here
(`review_experiment_summary__optimized_density_case_details.csv`).

Everything except the hardware-specific wall-time tables can be regenerated
from this repository alone; see the top-level README for the environment files
and the per-figure commands.

## Manifest

`MANIFEST.csv` lists every file with four columns:

| Column | Meaning |
| --- | --- |
| `file` | file name in this directory |
| `bytes` | size on disk |
| `sha256` | SHA-256 of the file contents |
| `supports` | the section, table, or figure of the article it feeds |

The hashes are over LF-normalized content; `.gitattributes` pins these files to
LF so they verify on any platform:

```
sha256sum -c <(awk -F, 'NR>1{print $3"  "$1}' MANIFEST.csv)
```

## Naming

File names are the source path with `/` replaced by a double underscore, so
`simp_floor_trajectories__cantilever__trajectory_iters.csv` was produced as
`cantilever/trajectory_iters.csv` by the `simp_floor_trajectories` stage. This
keeps the deposit flat while preserving which stage emitted each table.

## Notes on the contents

- Residuals are relative: `||f - Ku|| / ||f||`, FP64 throughout.
- Where a table carries both a projected and a recomputed residual, the projected
  value is the quantity the solver stopped on and the recomputed value is the
  quantity the article's acceptance test uses. The two disagreeing is the subject
  of the article, not an error in the table.
- `prospective_history.csv` files record every attempted solve, including
  attempts the acceptance guard rejected; `prospective_summary.csv` files record
  one row per state with the selected outcome.
- Seeds identify pseudo-random state families generated by a PCG64 generator
  seeded per row; the seed column reproduces the state exactly under the code in
  this repository.
- Wall times were measured on the configurations described in the article's
  reproducibility appendix and are not comparable across configurations.
- The tables are copied verbatim from the experiment outputs: no column was
  removed or renamed, and no value was altered. They were screened for absolute
  paths, user or machine names, and email addresses, and contain none.
